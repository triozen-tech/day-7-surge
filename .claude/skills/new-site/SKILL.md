# New showcase site

The user gives a brief like: *"Day [N] — [Brand], a sneaker brand. Black and neon green, energetic. Hero video in raw/hero.mp4."*

**First, and again at the start of every round: read `docs/LESSONS.md`.** Then follow `CLAUDE.md` → "Building a new site — Round 0 + 5 rounds". Never skip a round, and stop after each round for the user's "ok". Explain things in plain simple language.

**The repo shows only the current project** (see `CLAUDE.md`): old sites live in their own day folders; git holds only today's site, the engine, the pattern library and the kit docs.

- **Skills to use:** `flow-prompts` (assets), `video-frames` (every scroll video), `record-check` + `phone-check` (end of every round), `cover-check` (reel cover), `caption` (post text), `archive-day` (finish + commit), and the official `gsap-*` skills while coding motion. Effects M38+ and transitions X6+ are ready in `components/fx/` (see `/lab`); a travelling product object (F1–F8) in `components/fx/travel/` (see `/lab/travel/f1`, `/f3`, `/f6`): default to F1 (PNG) or F3 on OGL (the only 3D inside the budget).
- **Round 0 layouts:** for EVERY section pick a **SECTION-MENU layout code** (`docs/SECTION-MENU.md`, live at `/lab/sections`) **and** a MOTION-MENU code. No layout code twice on a site and none used by the last 3 sites (SITES-LOG → Layouts column, and the Layout row in that day's uniqueness table).
- **Round 0 — Design direction:** first delete the previous site's images and frames (`public/images/<old-slug>/`, `public/frames/<old-slug>-*`) and any demo assets, so only the new site's assets exist. Read `docs/SITES-LOG.md` + `docs/DESIGN-MENU.md` + `docs/MOTION-MENU.md`, pick one option per menu (≥ 6 of 8 different from each of the last 3 sites), plan 9–12 sections (hero + cinematic + shop-style), write `site/DESIGN.md`, list missing assets with prompts. The "different from the last sites" table goes in `docs/SITES-LOG.md` only (never in `DESIGN.md`, so old names never enter the repo). Wait for approval.
  - **`DESIGN.md` must include a "Motion map" table** (template at the end of `docs/MOTION-MENU.md`): every section, loader, nav and footer included → **one motion code** (M1–M37), how it plays here, phone fallback, record mode. **No code used twice. "Just fade in" is not allowed** as any section's motion. The hero and signature must not repeat **any** earlier site's hero or signature (check every row of `docs/SITES-LOG.md`, not just yesterday), and the hero must not be a "shape grows to full screen / portal" opening. Add the planned transitions (X codes) and details under the table.
- **Round 1 — Structure:** archive the old site, frames + images into per-site folders, install fonts, write `site/` from scratch (copy patterns into `site/components/` and restyle them), build the markup the Motion map needs, `npm run check` + `npm run build`. `npm run phone-shots` (fix anything cut off / overlapping). User reviews `http://localhost:3000/?static=1` on the laptop + the phone contact sheets.
- **Round 2 — Big motion:** loader, hero, signature moment and every pinned / scroll-scrubbed section; everything interactive also plays by itself on screen. **Motion map check.** Run the checks and send the user the 1440 reel.
- **Round 3 — Section motion + transitions:** every other section gets its Motion map code, plus the transitions between sections. **Motion map check.** Run the checks and send the user the 1440 reel.
- **Round 4 — Details + phone pass:** hover, cursor, micro-interactions (each with a hands-free version for filming), then a phone pass from screenshots (`npm run phone-shots`, 360×640 + 390×844): each section's phone fallback, the main subject fully visible with nothing on top of it (place videos by where the subject is in the frame, never a fixed crop), no sideways scroll, text ≥ 12px. **Motion map check** (1440 reel + phone screenshots). Send the 1440 reel.
- **Round 5 — Polish, performance, archive:** readability, performance, `?static=1` final states, console clean, set `meta.record.duration` (25–40 s), add a row to `docs/SITES-LOG.md` (with the Motion column), add the day's new lessons to the end of `docs/LESSONS.md`, `npm run archive -- <day-NN-slug>` (skill `archive-day`). Final checks: `npm run reel` (PASS), `npm run phone-shots` (clean), `npm run check`; send the 1440 reel. Then run `git ls-files` and confirm the repo holds only the current site's assets, the engine, the pattern library and the kit docs (no other brand names or images); report the list and total size. Reply with the filming steps from `docs/RECORDING.md`.
- **Checks every round** (production server: `npm run build && npm start`): **`npm run reel -- <slug>-r<N>`** records `?record=1` at **1440×900 only** and runs freezedetect + frame-diff; it must PASS (low fps = busy machine → re-run). **`npm run phone-shots`** = screenshots of every section at 360×640 and 390×844; the main subject must be fully visible with nothing overlapping it. Fix every problem before saying the round is done. **No phone recordings**; the user only gets the 1440 reel.
- **Motion map check (end of Rounds 2, 3, 4):** go through the Motion map section by section; the main move must be the planned code (not a fade), play without hover/click, and show its final state with `?static=1`. Fix any that don't match, and report a short table: section · code · ✅ / fixed.
- **Pattern library:** demos on `/patterns` use plain colour placeholders or the current site's images, never an old site's.
